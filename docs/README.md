# CPHOS 平台：旧系统调研 → 新系统设计 → 实现

> **方向定案（2026-08）**：完全放弃兼容性迁移，**重新设计一套系统**（TypeScript 全栈，pnpm monorepo）。**不导入任何历史数据**，字典由管理员按新系统功能重新录入；数据库 schema 使用 `prisma db push` 同步，**不保留迁移历史**。
> 登录：**全员账密登录**（平台用户=邮箱，内部账号=用户名）；邮箱验证码仅用于普通用户注册与敏感操作二次确认。
> 账号层级：**唯一**超级管理员（系统初始化、受保护不可删除）→ 管理员（超管从 CPHOS 内部用户提升、可降级）→ CPHOS 成员（内部建档，用户名+显示名+密码）→ 平台用户（邮箱+验证码注册，审核后开通）。**仲裁为功能模块，不再是身份。**

## 快速开始

```bash
pnpm install
pnpm dev:db            # 终端 1：内嵌 PostgreSQL（数据在 apps/api/.pgdata/）
pnpm api:migrate       # 终端 2：首次建表/同步 schema（prisma db push，无迁移历史）
pnpm api:seed-dev      # 终端 2：开发种子（合成字典，可反复执行）
pnpm dev:api           # 终端 3：API（http://127.0.0.1:3001）
pnpm dev:web           # 终端 4：前端（http://localhost:5173）
pnpm e2e               # 本地 E2E（自动拉起服务、复用本机 Edge）
pnpm api:init-super-admin -- super@example.com <密码>   # 超级管理员（受保护）
pnpm api:create-internal -- <邮箱> <密码> <姓名> ADMIN  # 管理员（审核工作台）
```

开发模式未配置 SMTP 时，验证码写入 `apps/api/.devmail/*.json` 并在 API 日志打印。

## 开发约定

- 每完成一个功能块，在会话中报告该块的设计与使用方式，与用户对齐后再进入下一块；
- 功能块进度：① 工程骨架 + 认证（✅）→ ② 审核与认领（✅ 核心，材料上传暂缓）→ ③ 用户域业务（✅ 账号安全 / 团队 / 字典 / 审计日志后端与界面）→ ④ 考试域（⬜ 下一步）→ ⑤ 排名/导出/收尾。
